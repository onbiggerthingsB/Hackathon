# Team delivery register

Updated November 2, 2026. This is a planning register, not a submission confirmation.

## Official requirements

The [challenge assignment](https://github.com/Pomfret-Coders/fallhackathon2026/blob/ed2c3a87e8b89172e2a42e21e164f2833e2efa8d/challenge/index.html#L37-L41) requires four simulations across four distinct academic departments. Each must use Matter.js as its central engine, be accessible through a public web link, prominently identify its department and specific class, and have an educational use. It may support a teacher-led demonstration or independent student exploration. See the [required features and judging criteria](https://github.com/Pomfret-Coders/fallhackathon2026/blob/ed2c3a87e8b89172e2a42e21e164f2833e2efa8d/challenge/index.html#L43-L89).

Entries are ranked within departments, earning 4, 3, 2, or 1 point for first through fourth place. Each entry can earn at most 4 points; four entries can earn at most 16. [Scoring rules](https://github.com/Pomfret-Coders/fallhackathon2026/blob/ed2c3a87e8b89172e2a42e21e164f2833e2efa8d/challenge/index.html#L91-L112)

Every member must contribute. In a shared repository, each member's GitHub identity must appear in the commit history. The organizer's form requires the repository link or links and all member GitHub usernames. Completed work must be pushed before the organizer downloads the repositories at the cutoff; later commits are excluded from that judged copy. [Submission rules](https://github.com/Pomfret-Coders/fallhackathon2026/blob/ed2c3a87e8b89172e2a42e21e164f2833e2efa8d/challenge/index.html#L134-L143)

The opening deck's eight technical exercises are preparation references. Whether every exercise must appear in the final work is unconfirmed. Hardware is not established as mandatory by the reviewed final challenge. Record any actual hardware requirements and tests in each member's handoff.

## Suggested readiness checks

These checks are team recommendations derived from the judging qualities, not additional organizer rules. Assign a teammate reviewer for each entry and record the date, tested URL or revision, outcome, and remaining issue in the member handoff.

| Official quality | Suggested review |
| --- | --- |
| Useful | State the learning objective and have a reviewer explain the concept after using the simulation. Check that Matter.js drives the lesson and the behavior supports the intended explanation. |
| Beautiful | Check visual hierarchy, readable labels, coherent type and color, and whether motion helps explain the lesson. |
| Smooth | Have someone unfamiliar with the code open the public URL, understand the controls, complete the activity, and recover using reset where provided. Check keyboard access, a narrow viewport, and repeated interaction. |
